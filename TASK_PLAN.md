## 1. Что уже есть в репозитории (прототип «Лекция_3»)

Полностью рабочий мультиагентный трекер публикаций, а не заготовка:

- **Оркестратор** `main.py::process_items` — цикл: поиск → текст → резюме → (почта выкл).
- **Координатор** `scraper.py::get_new_items` — опрашивает агенты-источники, фильтрует историю, зовёт валидатор.
- **Агенты-источники** (4 шт.): `archive_agent.py` (archive.org), `arxiv_agent.py` (arXiv),
  `openalex_agent.py` (OpenAlex), `habr_agent.py` (Habr RSS).
- **Валидатор** `validator.py` — проверяет, что все слова темы есть в заголовке/аннотации/странице.
- **Суммаризатор** `summarizer.py` — Sumy LSA (по умолчанию) или LLM (Ollama / OpenAI-совместимый).
- **Нотификатор** `notifier.py` — SMTP, в UI выключен.
- **Streamlit-панель** `streamlit_app.py` — темы, источники, даты, резюме, вкладка «Схема агентов», журнал.
- **Тесты** `tests/test_agents_offline.py` — офлайн-проверки контрактов агентов (без сети).
- **Схема** `diagr/agents.html` / `.png` — готова для презентации.

Контракт нового источника (важно для добавления наших двух):

> Модуль с `SOURCE_ID`, `SOURCE_NAME` и `fetch(topics, rows=20, date_from=None, date_to=None)`,
> возвращает список словарей `{source, identifier, title, url, abstract, ...}`.
> Регистрация — в словаре `SOURCES` в `scraper.py`, идентификатор — в `config.yaml`.
> Если источник отдаёт полную аннотацию в метаданных — добавить его id в
> `SOURCES_WITH_ABSTRACT` в `validator.py`, чтобы валидатор не качал страницу.

Наша версия новее оригинала EdwFa/MAS/Лекция_3: там только archive.org + arXiv,
у нас добавлены OpenAlex и Habr, провайдеры LLM и офлайн-тесты.

## 3. Выбранные источники: анализ

### 3.1. Europe PMC — низкий риск, делать первым

- Бесплатный REST API без ключа: `https://www.ebi.ac.uk/europepmc/webservices/rest/search`
- `resultType=core` отдаёт: аннотацию (`abstractText`), авторов, журнал, DOI, даты
  (`firstPublicationDate`, `pubYear`), `fullTextUrlList`, `citedByCount`, ключевые слова, MeSH.
- Язык запросов: `TITLE:"…"`, `ABSTRACT:"…"`, `FIRST_PDATE:[2025-01-01 TO 2025-12-31]`, `SRC:MED` / `SRC:PPR`.
- Проверено живьём: по запросу «medical multi-agent» отдаёт релевантные статьи с аннотациями.
- Ложится на контракт агента один в один (образец — `openalex_agent.py`).
- Нюансы: чистить HTML-теги (`<i>…</i>`) в заголовках; сортировка по дате — клиентская
  (по `firstPublicationDate`); добавить id в `SOURCES_WITH_ABSTRACT`.

### 3.2. Рубрикатор КР Минздрава РФ (cr.minzdrav.gov.ru) — главный риск

- Официальный единственный источник клинических рекомендаций с юр. силой (ст. 37 ФЗ-323),
  >1500 документов, поиск по названию/синонимам/МКБ-10, карточки: номер, редакция, год, разработчик.
- **Публичного API нет.** Сайт не отдался автоматическому fetch (вероятно JS/антибот) —
  нужна разведка внутреннего поиска (сетевые запросы) и, скорее всего, скрейпинг HTML.
- **Дат «последняя неделя» у КР нет** — есть год утверждения и номер редакции, документы
  обновляются редко. `date_from/date_to` придётся игнорировать или маппить на год.
- **Русский язык:** Sumy-суммаризатор с английским токенизатором на русском тексте не сработает —
  нужен fallback (первые N предложений аннотации) или LLM-провайдер. Валидатор частично ок
  (regex `\w` в Python unicode-aware), но `token_is_exact` работает только для латиницы.
- Запасной вариант, если официальный сайт не отдаст данные: независимый рубрикатор
  `clinirec.ru` (синхронизируется с официальным) или `femb.ru` — но преподаватель согласовывал
  именно Минздрав, поэтому сначала пробуем официальный.
