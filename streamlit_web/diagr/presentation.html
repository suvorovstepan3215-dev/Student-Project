Учебный проект · Мультиагентные системы

Трекер медицинских публикаций

Мультиагентный поиск по научным статьям и клиническим рекомендациям: запрос → лексическая проверка релевантности → экстрактивное резюме. Веб-интерфейс (Streamlit) и отдельный MCP-сервер по stdio.

Что на входе

Темы на естественном языке («diabetes», «сахарный диабет»), диапазон дат, источники. На выходе — карточки найденных записей с резюме, методом резюме, происхождением данных и диагностикой источников.

Это учебный инструмент поиска и сжатия текста. Не медицинская рекомендация, не проверка достоверности публикаций и не замена чтению клинической рекомендации.
01 · Задача

Кому и зачем

Вопросы, на которые отвечаем

  • Что нового опубликовали по теме за неделю / месяц?
  • Какие клинические рекомендации РФ актуальны сейчас?
  • Какую запись читать первой и почему (резюме в три предложения)?
  • Откуда взялись данные и можно ли им верить слепо?

Чего принципиально не делаем

  • Не даём медицинских советов и не назначаем лечения.
  • Не проверяем факты статьи (лексика ≠ фактчекинг).
  • Не выдаём метаданные каталога КР за текст рекомендации.
  • Не отправляем анонимные запросы к платным LLM.

Streamlit вызывает Python напрямую. MCP — отдельный stdio-интерфейс, это не URL сайта и не медицинский чат.

04 · Как это работает

Пять шагов поиска

  1. Запрос. Темы по одной в строке; для Европы удобнее английский, для КР — русский или код МКБ-10. Алиасы (E10–E14) настраиваются в конфиге сервера.
  2. Обход источников. Каждый источник возвращает записи или честные errors/warnings; ошибка источника ≠ «ничего не найдено».
  3. Лексическая проверка. Слова темы / русские основы; для КР-карточек сверяются заголовок, коды МКБ-10 и возрастная категория.
  4. Резюме. Локальный Sumy LSA для EN и RU (без LLM и без ключей); при сбое — первые предложения с явной пометкой.
  5. Выдача. Карточки и таблица: метод резюме, происхождение данных, предупреждения; история — только в сеансе браузера.
05 · Честно

Ограничения и правила честности

  • Зеркало КР — не официальный источник. Оно знает только год пересмотра; актуальность и соответствие официальным КР не проверяются.
  • Карточка КР ≠ резюме. Показывается описание метаданных (МКБ-10, возраст, год), не текст клинической рекомендации.
  • Ошибка источника ≠ отсутствие публикаций. В интерфейсе видны статус каждого источника и текст сбоя без секретов.
  • Без LLM по умолчанию. Публичный режим: анонимных запросов к платным моделям нет; резюме строится локально.
  • Секреты — только на сервере. Ключи не вводятся в браузере и не сохраняются в сеансе.
  • История — в пределах сеанса. Просмотренные записи можно пропускать в рамках текущего открытого окна.
06 · Демо

Как показать за две минуты

  1. Темы: diabetes и сахарный диабет; период для статей — «Месяц», для КР — «Произвольный» с 2020 (зеркало знает только год).
  2. Источники по умолчанию: Europe PMC + OpenAlex + Каталог КР. Строк с источника — 10.
  3. «Запустить поиск сейчас». Смотрите метод резюме: у ePMC сегодня нет текста — OpenAlex почти всегда даёт аннотацию.
  4. Карточка: «Открыть запись источника», «Перевести резюме», предупреждения внизу списка. Таблица — для выгрузки глазами.

Страховка на выступлении

Если внешняя сеть подведёт — живой поиск честно скажет об ошибке; офлайн-часть (интерфейс, карточки, таблица) работает всегда.

07 · Дальше

Куда развивать

  • Официальный API Минздрава (apicr.minzdrav.gov.ru) — уже реализован в адаптере (режим auto); нужна доступная из сети точка входа.
  • Полный текст открытого доступа: Europe PMC fullTextXML для OA-статей — резюме по тексту, а не по аннотации.
  • Реестр medinfo: PubMed E-utilities, Unpaywall, киберЛенинка — как следующие адаптеры тем же интерфейсом.
  • Метрики качества: доля записей с резюме, ложные совпадения лексики — на реальных запросах семинара.
